# 保存メタの保全修復

一部の計画で、実際の保存行より `ENG_SHEETS.last_row` が小さくなり、計画を読み込めなかった。仮の着地を追加する処理が、行だけを保存して復元用の寸法・指紋を更新していなかったため。新しい保存では、同じ Journal にメタの更新も含める。

既存データは予測の再計算や仮行の再生成で直さない。所有者が対象計画を明示し、既存行から `OUTPUT`・`EVAL_COMPARE_MONTHLY`・`PROCESS_STATUS` の寸法と指紋だけを修復する。アプリの版・乱数の種・計算本体は変更しない。

## 操作

Apps Script のスクリプトプロパティ `OWNER_TASK` に JSON を入れ、所有者として `apiOwnerTask` を実行する。実際の計画ID・Drive ID・指紋は非公開の実行記録に置き、公開リポジトリへ載せない。

1. `{"action":"previewNativeMetadataRepair","planIds":["PL-対象"]}` で変更件数と `previewSha256` を確認する。データを書かない。
2. データブック全体を同じ非公開の保管先へ複製する。
3. `{"action":"applyNativeMetadataRepair","planIds":["PL-対象"],"previewSha256":"確認した64桁の指紋","backupId":"退避版ID"}` を実行する。

適用はロック内で行い、未完了の Journal・動作中のジョブ・まとめて動かす処理・締めた年度を拒否する。確認時の指紋と、現在／退避版の全表の値・型・数式・表示形式・locale・time zone が一致した場合だけ進む。欠けたメタ、不正なJSON、重複、重なりや過大な復元範囲も修復せず停止する。

書込前に、変更前後のメタと全表の指紋を非公開の修復控えへ保存する。既存 Journal の `replacePlan` を1メタキーずつ使い、更新時刻を含めた値を固定する。対象行の文字列形式と全メタキーを事前検査し、変更後には、非メタ全表が不変で、メタ表全体が指定キー・指定列だけの変更になったことを照合する。成功は控えの `VERIFIED` で確認する。

## 中断・巻戻し

- Journal が未完了なら、既存の回復処理で完了させてから次へ進む。
- Journal が完了し、控えだけ `PREPARED` の場合は `{"action":"resumeNativeMetadataRepair","repairFileId":"控えID"}`。現在の全表が変更後の指紋に一致する場合だけ控えを確定する。
- `{"action":"rollbackNativeMetadataRepair","repairFileId":"控えID"}` は、修復後に別の保存がない場合だけ当該メタ列を元へ戻す。ブック全体の上書きはしない。元の全表の指紋に戻ったことを確認し、控えを `ROLLED_BACK` にする。
- 巻戻し完了後に控えの更新だけが止まっても、再実行で確定できる。後続の人の保存があれば巻戻しも再開も拒否する。

自動適用や起動時の黙示修復はしない。模擬テストと本番の保全照合・公開版の読戻し・ブラウザ確認は別に記録する。
