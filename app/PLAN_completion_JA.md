## 作業する環境

- 正本は 2 つのリポジトリです。
  - `yukihiro-murai/gas-workspace`（非公開）: ルートの `AGENTS.md`・`GIT_SYNC_RULES.md`・`.ai/`
  - `yukihiro-murai/Trends2Targets`（**公開**。2026-10-06 に Forecast_Agent から改名）: このアプリ
- Mac 以外の環境（クラウドの VM など）では、両方を同じ親ディレクトリに clone します（`gas-workspace/` の中に `Trends2Targets/` を置くと Mac と同じ形になります）。
- **このリポジトリは公開です。** ルートの規約や `.ai/` の中身を、このリポジトリへ写さないでください。
- `clasp push` / `clasp deploy` は、村井さんの Mac でだけ行います。それ以外の環境では、テスト・commit・push までにとどめます。
  - 公開してほしい commit は、`.ai` タスクの Next action に「公開待ち: <commit>」と書きます。

## 完成形

1. 社内のメンバーが、アプリの画面だけで 1 年を回せる。
   - 計画を作る → 取り込み（A-2・B-1）→ AI 調査（A-4）→ 予測 → 入力 → 予算 → 公式版を出す → 承認
   - 検証と学習（B-2〜B-5）→ 四半期レビュー（C-1・C-3）
   - 年度の切り替え
2. 公開範囲は社内ドメインで、役割（予算策定担当・承認者・管理者）が付いている。ファイルは誰にも共有しない。
3. 毎日の運用（バックアップ・手入れ・監査の鎖の確認）は自動で動く。異常は管理者に届く。
4. 利用者向けの使い方と管理者向けの運用手順（復元・権限・年度の切り替え）が、`app/README.md` の 1 か所にある。

## 段階

各段のやり方は同じです。
1. テストを足す。
2. テストを全部通す。
3. commit・push する。
4. `clasp status` → `clasp push -f` → `clasp deploy -i <ID>`（同じ URL）で公開する。
5. 公開した版の中身が Git と同じかを確かめる。

**公開範囲・権限（scope）・保存先を変えるものは、必ず村井さんの明示の承認を得てから行います。**

## 守ること（要約。正本は `AGENTS.md`・`.ai/README.md`・`app/README.md`・`DESIGN_evolution_JA.md`）

**変えないもの・消さないもの**
- 計算・保存・権限・予測の判定のロジックは、村井さんの判断なしに変えません。

- 作業の初めに fetch / pull します。
- 終わりに commit → `pull --ff-only` → push します。
